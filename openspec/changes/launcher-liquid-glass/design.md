# Design

## Context

动机与变更范围见 `proposal.md`，用户已选定本轮概念图的第二张。该图随本变更保存在 `assets/launcher-liquid-glass-reference.png`，作为布局与视觉层次的参照。

![用户选定的第二张液态玻璃启动器概念图](/Users/Sampwood/Documents/code/self/invoker/openspec/changes/launcher-liquid-glass/assets/launcher-liquid-glass-reference.png)

当前实现与本次设计有关的事实：

- `LauncherView` 使用一个固定 680 × 430 pt 的容器、`.regularMaterial` 背景、72 pt 搜索区、58 pt 结果行和实心强调色选中背景。
- `LauncherPanelController` 将视图放在单个透明、无边框的 `NSPanel` 内；窗口创建和鼠标所在屏幕居中都依赖 `LauncherMetrics.width/height`，系统窗口阴影已关闭。
- `ClipboardHistoryView` 已有 `.glassEffect(.regular, in:)`、减少透明度回退、语义文字颜色和内容外阴影留白；可以沿用这些做法，不需要抽取共享组件。
- 现有推荐、选择和执行由 `LauncherSearchViewModel` 管理。相关测试已覆盖五项推荐、不限制搜索数量、选择边界、刷新保留查询和成功执行统计，不需要为视觉改版重写这些逻辑。
- Xcode 工程当前所有部署目标均为 macOS 26.0。README 仍写 macOS 13，这是已有文档差异；本次不修改部署配置，也不承诺新增旧版本支持。

本设计需要提前确定分离玻璃表面的组合方式、窗口留白和无障碍回退，因此创建设计文档。

## Goals / Non-Goals

**Goals:**

- 在现有 SwiftUI 与 AppKit 结构内还原第二张图的双表面布局、轻量行样式和键帽层次。
- 将可见内容尺寸与用于容纳阴影的宿主窗口尺寸区分，保证居中和完整显示。
- 用系统材质与语义颜色处理背景、外观和无障碍变化，保留可读性。

**Non-Goals:**

- 不制作网页原型、自定义玻璃着色器、桌面截图背景或持续播放的装饰动画。
- 不增加第三张图的底部操作提示、分组、筛选、页签或新的快捷键。
- 不改变搜索、推荐、扫描、统计或执行规则，不扩展到其他功能面板。
- 不新增主题设置、全局设计系统或兼容旧系统的分支。

## Decisions

### 1. 第二张图确定结构，数据与背景保持真实

保留上方完整胶囊、下方独立大圆角面板、可见间距以及两者左右对齐的关系。结果列表仍按现有数据生成；图中的 KeePassXC 和四条命令只是示例，首次打开仍默认选择实际推荐首项。

应用继续使用 `LauncherIconCache` 的原始图标；命令使用现有 SF Symbols，移除厚重的统一白色图标底块。标题、描述和快捷键保持现有内容及单行截断规则。快捷键以紧凑圆角键帽呈现，保留完整宽度，不成为独立按钮。

沿用搜索字号 20 pt、标题 14 pt、描述和快捷键 11 pt、图标槽 30 pt，以本机渲染后的可读性微调间距。无须增加文案或国际化文件。图中的蓝紫壁纸与光斑不进入应用资源；真实桌面决定玻璃透出的色彩。

备选方案是只替换原整块容器背景，但那无法表达已选图中的独立搜索胶囊；因此不采用。

### 2. 两个玻璃表面，共用一个窗口

继续使用一个 `NSPanel` 和 `NSHostingView`。在 `LauncherView` 中，将现有搜索内容与结果内容分别放入胶囊和连续圆角矩形，外层不再绘制连接两块表面的背景、边框或分隔线。

采用一个 `GlassEffectContainer(spacing: 0)` 管理两个 `.glassEffect(.regular, in:)` 表面，内部布局保留 8 pt 间距，以避免两块玻璃在静止时融合。尺寸、内边距先确定，再应用玻璃效果。无需 `glassEffectUnion`、形变 ID 或自定义折射实现。

`regular` 作为两块表面的初始材质，原因是启动器必须在不可控的桌面背景上承载文字。原生材质负责折射与边缘光感，不叠加大面积固定白色蒙层或多重发光描边。选中条与键帽通过普通低透明度填充及细轮廓表达层次，不再逐行叠加真正的玻璃效果。

备选方案包括两个独立窗口、全透明 `clear` 材质及每行独立玻璃。前者增加焦点和关闭同步成本，后两者增加阅读和材质叠加风险，均不作为本次方案。

### 3. 显式区分可见布局与阴影留白

在现有 `LauncherMetrics` 中集中维护尺寸，初始值如下；这是实现起点，最终外观通过开发者人工核对选定图确认。

| 项目 | 初始值 |
| --- | --- |
| 可见内容宽度 | 680 pt |
| 两块表面及中间间距的总高度 | 430 pt |
| 搜索胶囊高度 | 64 pt |
| 表面间距 | 8 pt |
| 结果面板高度 | 358 pt，由总高度减去搜索高度和间距得到 |
| 结果面板圆角 | 24 pt |
| 行高 / 行间距 | 58 / 4 pt |
| 列表水平及垂直内边距 | 10 pt |
| 外部阴影留白 | 四边各 20 pt |
| 宿主窗口尺寸 | 720 × 470 pt，由可见内容与留白派生 |

搜索形状使用胶囊，选中行使用接近胶囊的圆角轮廓并向结果面板内侧缩进。搜索、结果、扫描和空状态不改变整体高度。五行推荐需要 326 pt（五行、四处行间距、上下内边距），结果面板剩余空间容纳一行扫描提示，避免扫描时第五行被挤出。

沿用剪贴板面板的对称留白和轻阴影做法。宿主窗口保持透明且 `hasShadow = false`，SwiftUI 阴影在预留区域内绘制。窗口创建与 `centeredPresentationOrigin()` 同步使用新的窗口宽高，对称留白使可见内容中心与窗口中心一致。

继续使用现有窗口级点击和焦点管理。两块表面之间的透明间距及阴影留白属于同一宿主窗口，点击这些区域不执行命令、不穿透到后方窗口；点击宿主窗口之外或失去焦点仍关闭。无需引入跨窗口协调或自定义穿透区域。

备选方案是按结果数量动态改变窗口高度；它会引入输入时的位置与尺寸变化，本次保留固定布局。

### 4. 将玻璃样式与选择状态分开处理

继续以 `viewModel.selectedCommandID` 为唯一选择来源，保留按钮动作、悬停选择、方向键、回车和滚动跟随。

- 普通选中态使用低透明度系统强调色填充及细轮廓；默认系统蓝对应概念图的浅蓝效果，文字继续使用 `labelColor`、`secondaryLabelColor` 等语义颜色，避免沿用实心蓝底时的固定白字。
- 深色外观仍由系统颜色和材质响应，不固定为概念图的浅色背景。
- 减少透明度时，两块表面改用 `windowBackgroundColor` 不透明背景，保留原形状、间距和选中提示。
- 增强对比度时，提高选中轮廓及键帽边界的对比；非颜色区分时使用更明确的选中轮廓，维持第二张图的形状语言。
- 减少动态效果时，现有 `proxy.scrollTo` 直接执行，新增的选择过渡也关闭；不额外增加形变或弹跳动画。
- 玻璃描边和键帽是装饰。保留搜索框、清除按钮和结果按钮的辅助功能语义，选中项提供选中状态，不制造额外焦点。

减少透明度、增强对比度和减少动态效果是这次玻璃设计需要补齐的基本可用性要求，不扩展为独立设置或通用样式系统。

### 5. 验证以真实桌面和现有行为为准

实施后由开发者进行视觉和交互验收：浅色、深色、图案密集背景；正常与无障碍外观；推荐、扫描、空结果、超过五条的滚动结果；长文本及快捷键同时显示。图像只约束布局、形状和层次，不要求复刻生成图中不可控的光学细节。

保留现有 `LauncherTests` 的行为回归范围。对新布局增加一条小型容量断言或测试，检查扫描提示与五行推荐能同时容纳，避免只测试常量相等。不建立截图测试框架，也不通过真实应用启动测试产生额外副作用。

遵循当前开发流程：修改完成后交由开发者人工验证；构建和会触发构建的测试执行须另行得到请求。未执行的检查保持未验证状态。

## Risks / Trade-offs

- [概念图比真实系统材质更通透或具有更强边缘高光] → 优先匹配分离布局、胶囊形状、轻量高亮和文字层次，实际折射由系统提供。
- [复杂背景导致描述或快捷键对比不足] → 使用 `regular` 材质与语义颜色，并将浅色、深色和密集图案背景列为人工验收项。
- [两个玻璃表面被容器融合] → 玻璃容器融合间距设为 0，布局间距保持正值，检查静止和输入状态下均分离。
- [新增阴影被窗口裁切或可见内容偏离居中] → 对称预留阴影空间，同步更新视图框架、窗口尺寸与居中计算。
- [扫描提示压缩列表] → 固定结果面板高度，并对扫描提示与五行推荐的总容量做一项轻量检查。
- [README 的系统要求与工程不一致] → 将此记录为已有文档差异；本变更保持工程配置，不宣称修复或扩展兼容性。

## Migration Plan

无数据、配置或依赖迁移。实施范围以启动器视图、尺寸定义及窗口几何使用点为主，新增检查放在现有测试体系或局部开发断言中。开发者完成验收后按项目原发布流程交付；需要回退时撤回本变更的界面与几何修改，不修改使用历史或应用索引。
