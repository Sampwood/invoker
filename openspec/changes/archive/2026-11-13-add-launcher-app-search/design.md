# Design

## Context

动机见 `proposal.md`。已检查的实现如下：

- `LauncherCommandRegistry` 存放八个命令，并按名称、关键词、描述计算匹配优先级。
- `LauncherSearchViewModel` 只返回命令，选择状态为命令 ID；`prepare()` 清空输入，默认选择首个命令。
- `LauncherPanelController` 统一处理方向键、回车、Esc 和关闭事件，执行前关闭面板。
- `LauncherView` 假定所有结果均为 SF Symbols 图标的命令，搜索与空状态文案也仅提及命令。
- `StatusBarController` 注册命令及快捷键，负责面板之间的切换。
- 现有测试采用 XCTest，尚无 Launcher 专属测试。Xcode 工程显式登记源文件，Swift 版本为 6.0，当前 deployment target 为 macOS 26.0；README 中的 macOS 13 描述与工程不一致。本次以工程配置为编译基线，不调整系统支持范围。

## Goals / Non-Goals

**Goals:**

- 扩展现有 Launcher，使应用与命令共享搜索、选择和执行入口。
- 将文件扫描与主线程 UI 隔离，通过可注入边界验证文件发现和启动路由。
- 对缓存结果、异步刷新和启动错误给出确定的处理方式。
- 用同一份本地使用统计驱动空查询推荐和非空查询排序。

**Non-Goals:**

- 不抽象成通用插件框架，不建立数据库或常驻全盘索引。
- 不重构翻译、剪贴板等命令内部逻辑；此次保留的是现有执行路由，不顺带修复其潜在的前台焦点问题。
- 不调整现有窗口尺寸、快捷键注册方式或项目系统版本配置。

## Decisions

### 1. 使用受限目录扫描和内存快照

新增 `LauncherApplication` 数据模型和 `LauncherApplicationScanner`；刷新任务及内存快照由 `LauncherSearchViewModel` 持有。通过 Foundation 枚举提案定义的三个根目录；进入普通子目录，在 `.app` 边界停止递归，跳过隐藏项和其他包内部。普通目录符号链接不跟随，应用符号链接解析为目标后校验并按实际路径去重，避免目录循环。读取应用元数据，检查包类型为应用且声明的可执行文件存在；不要为读取元数据执行任何应用代码。

每个应用保存规范化 URL、本地化显示名称、文件名别名及稳定 ID。显示名称优先采用本地化 `CFBundleDisplayName`，其次本地化 `CFBundleName`、普通对应字段，最后使用去掉后缀的文件名。使用实际路径生成带 `app:` 前缀的 ID；不同路径的副本仍保留。路径只用于内部身份、去重及确切启动，不传入行文案或悬停提示。

选择受限目录扫描，原因是范围明确且测试不依赖 Spotlight 索引状态。替代方案为 Spotlight 查询，可以扩大应用覆盖面，但引入索引缺失与外部卷范围问题；首期暂不采用。扫描范围外的应用属于本期已记录的范围限制。

### 2. 复用命令注册表，新增统一结果模型

保留 `LauncherCommand` 和现有注册数据，增加 `LauncherSearchResult` 枚举（命令／应用）以及统一的 ID、标题、副标题和图标描述。命令 ID 增加 `command:` 命名空间；视图模型选择状态改为结果 ID。命令与应用的执行保持显式类型分派，避免通过标题猜测动作。

保留现有匹配条件：名称完全匹配、前缀、包含、关键词、描述、组合文本。应用仅参与前三档，在显示名称和文件名别名中取最佳等级。非空搜索先过滤不匹配项，再按近 30 天次数降序、窗口内最近使用时间降序、匹配等级、类型（命令先）、本地化名称、稳定 ID 排序。频次是第一依据，即高频子串匹配可以排在低频完整匹配之前；不限制搜索结果数量。

空查询合并全部命令与已有应用快照，按次数降序、最近使用时间降序、本地化名称、类型、稳定 ID 排序后取前 5 项。未使用项计零次、无最近使用时间，按相同规则补位；不再按命令注册顺序填充默认列表。只有当前候选参与推荐，历史中已经卸载的应用不产生额外结果。打开及查询改变时选择当前结果首项，异步扫描完成时保留仍在可见列表中的选择。

替代方案是把应用包装为动态 `LauncherCommand`。虽然改动较少，但会把异步刷新、应用元数据和启动错误塞进命令闭包，不利于区分结果类型及验证失败行为，因此使用一个轻量枚举即可。

### 3. 后台刷新，主线程发布

首次打开即后台扫描，之后每次打开刷新；若扫描正在进行则复用该任务，不重复启动扫描。扫描、元数据读取和去重在后台串行执行，仅传递可安全跨并发边界的数据；SwiftUI 状态发布及 AppKit 操作回到主线程。不要在视图 `body` 或主线程同步计算属性中枚举目录。

刷新时保留上次快照供即时推荐、搜索和执行，不能因 isLoading 清空结果、禁用应用行或阻止启动。完成后一次替换；局部目录失败保留其他成功目录的结果，失败目录的旧结果移除，避免继续展示无法确认的条目。扫描完成按最新 query 和使用统计计算结果并调用选择协调逻辑：保留仍在可见结果中的选择，否则选首项。用户主动修改 query 则选新首项。

关闭面板允许当前扫描完成并更新缓存，但完成回调不得激活应用、显示窗口或请求搜索焦点。应用索引不落盘；应用重启后重新扫描，首轮扫描前只有命令候选，扫描后应用加入推荐。使用统计单独持久化，不依赖索引生命周期。替代的文件监听方案增加生命周期和事件合并复杂度，本期使用每次打开刷新。

### 4. 复用现有列表，补充应用展示

保留一个扁平列表及现有 680 × 430 面板尺寸，搜索提示改为“搜索命令或应用”。应用行只展示实际图标和显示名称，不显示路径，也不提供路径帮助提示。同名应用继续作为不同身份的结果存在，以各自图标和名称展示；本期接受同名同图标副本在视觉上难以区分的限制，不用路径补充说明。命令行继续使用现有 SF Symbols、描述和快捷键提示。

应用图标按可见行惰性读取并按路径缓存，在主线程使用 AppKit 提供图标，缺失时回退通用图标；不把 NSImage 放进后台扫描结果跨线程传递。扫描状态使用独立的小型状态提示，不能把尚在扫描时的空列表直接当成最终无结果。扫描结束且列表为空时显示统一无结果文案。

### 5. 通过系统工作区启动应用

新增可注入的 `LauncherApplicationLaunching` 边界，由基于 `NSWorkspace` 的实现按确切应用 URL 请求打开并激活，不强制新实例。`LauncherPanelController` 先关闭面板，再按结果类型执行命令或应用启动。

启动前检查目标仍有效，并处理系统异步完成回调中的错误；文件不存在、权限不足、系统拒绝等均展示“无法打开「应用名称」”及可理解的原因。失败不会按名称寻找替代应用，也不会自动重开启动器。用系统启动 API 而非 shell 拼接路径，避免路径转义问题，并让系统负责已有进程和正常启动策略。

### 6. 本地使用统计与近期窗口

新增可注入时钟及 UserDefaults 的 `LauncherUsageStore`，以统一结果 ID 保存近 30 天的使用时间戳列表，采用版本化专用 key 与 Codable 编码。项目现有剪贴板和翻译设置已使用 UserDefaults；使用相同方式，不引入数据库。读取、记录及生成排序快照时清理窗口外时间戳，窗口为 `[now - 30 × 24 小时, now]`，无记录的候选次数为零。一次结果计算使用同一个 now 快照，避免排序比较中跨越边界。

30 天是对“最近”的默认解释，次数相同再用窗口内最新一次时间决胜；完全无记录时采用稳定名称顺序。选择滚动窗口而非终身累计，是为了让近期习惯影响推荐，避免很久以前的高频项长期占位。此默认统计窗口和冷启动策略已列入提案，便于审阅调整。

仅统计 Launcher 的明确执行：命令在调用原 action 前记录一次，确保退出命令也能保存；应用在启动／激活成功回调中记录一次，失败不计数。不要在选中行、过滤搜索、扫描发现时记录，也不采集菜单栏、独立快捷键或其他程序产生的使用行为。回车和点击使用同一记录入口，避免双计数。

使用统计在 App 生命周期内共享，完成回调不依赖面板是否可见。统计更新时重新计算当前结果并保留仍可见的选中项；不得因此显示窗口。坏数据回退空统计；持久化故障不阻止执行，可保留本次运行的内存统计。应用移动导致路径 ID 变化时视为新候选，不按名称迁移统计。回滚时旧版本忽略专用 key。

## Risks / Trade-offs

- [标准目录不覆盖任意磁盘位置] → 在 README 和能力规范明确范围；全盘及自定义目录留作后续独立需求。
- [应用数量较多或路径读取较慢] → 后台扫描、已有快照即时搜索、单个在途任务；手动验证输入和关闭操作不受扫描阻塞。
- [应用在扫描后移动或卸载] → 执行前校验并处理启动回调失败，下次打开刷新索引。
- [刷新时结果排序变化导致误操作] → 保留有效选中 ID，执行时以当前选中结果的身份分派。
- [频次改变排序后命令不易发现] → 保留所有原匹配条件和动作，非空搜索不设 5 项上限，验证高频优先与八项命令可搜索执行。
- [没有使用记录或记录已过期] → 使用稳定名称顺序补足推荐；注入时钟测试窗口边界、重启恢复和损坏回退。
- [同名同图标副本视觉一致] → 按用户要求不展示路径，内部保留独立 ID 和精确目标，测试点击执行不会串到同名副本。
- [窗口关闭后启动失败反馈丢失] → 启动服务保持到异步完成，错误在主线程展示独立提示，不依赖可见的结果行。

## Migration Plan

按任务清单实现新模型、目录服务和使用统计，再连接推荐排序、UI、启动和工程文件；运行目标测试与手动验收后更新 README。首次使用专用统计 key 为空，从零开始，不迁移旧数据。无需权限迁移或新增第三方包。回退时撤销本变更的代码与工程引用即可，原命令注册数据继续可用，旧版本忽略新增统计 key。
